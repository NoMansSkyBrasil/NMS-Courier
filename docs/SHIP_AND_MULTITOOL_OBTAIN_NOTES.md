# Getting a new starship or multi-tool

Status on 2026-10-08: **implemented in bridge 1.7.0 and application 1.9.0, not
yet exercised against the running game.** Build 180836 only. The player gets a
new starship or multi-tool of a chosen kind, seed and class through the game's
own reward routine and offer screen, where they add it to the collection,
trade the current one or decline. It is a slot change.

## What the game has

The reward table holds 89 specific-ship rewards and 51 specific-weapon rewards
(expedition ships and multi-tools, platform rewards and so on). Each names a
model scene, a seed, a class, an inventory with the installed technologies, a
type and whether it is a gift. Giving such a reward opens the game's
comparison and offer screen.

Layouts, read from the 180836 `rewardtable.mbin` and verified against every
reward entry that consists of exactly one such reward (78 ships, 41
multi-tools):

| Field | Specific ship (class hash `0x8a37c4a2`) | Specific weapon (`0x5f82ff34`) |
| --- | --- | --- |
| Class (0 C, 1 B, 2 A, 3 S) | +0x40 | +0x40 |
| Model scene (a text reference) | +0x1c8 | +0x180 |
| Seed (64 bits) | +0x1e8 | +0x190 |
| Layout seed | +0x220 | +0x1a0 |
| Layout slots | +0x234 | +0x1b4 |
| Size type | +0x244 | +0x1b8 |
| Type | +0x248 | +0x1bc |

Ship types: 0 freighter, 1 hauler (`Dropship`), 2 fighter, 3 explorer
(`Scientific`), 4 shuttle, 6 exotic (`Royal`), 7 living (`Alien`), 8 solar
(`Sail`), 9 sentinel (`Robot`). Weapon types: 0 pistol, 1 rifle, 2
experimental (`Pristine`), 3 alien, 9 staff.

## How it is delivered

Same carrier method as currencies and items
([currency notes](CURRENCY_DELIVERY_NOTES.md)). The data file has one carrier
per kind, a copy of a reward the game ships for that kind (so the installed
technologies are the game's own for the kind), with the kind's procedural
scene, seed 1, class S and no special name. It is generated by
`runtime/research/build-courier-reward-table.py`.

| Kind | Carrier | Scene |
| --- | --- | --- |
| Fighter | `COURIER_SHIP_FGT` | `FIGHTERS/FIGHTER_PROC` |
| Hauler | `COURIER_SHIP_DRP` | `DROPSHIPS/DROPSHIP_PROC` |
| Explorer | `COURIER_SHIP_SCI` | `SCIENTIFIC/SCIENTIFIC_PROC` |
| Shuttle | `COURIER_SHIP_SHT` | `SHUTTLE/SHUTTLE_PROC` |
| Solar | `COURIER_SHIP_SAL` | `SAILSHIP/SAILSHIP_PROC` |
| Exotic | `COURIER_SHIP_ROY` | `S-CLASS/S-CLASS_PROC` |
| Living ship | `COURIER_SHIP_ALN` | `S-CLASS/BIOPARTS/BIOSHIP_PROC` |
| Interceptor | `COURIER_SHIP_RBT` | `SENTINELSHIP/SENTINELSHIP_PROC` |
| Pistol, rifle, experimental, alien multi-tool | `COURIER_TOOL_PST`, `_RFL`, `_EXP`, `_ALN` | `WEAPONS/MULTITOOL/MULTITOOL` |
| Staff | `COURIER_TOOL_STF` | `WEAPONS/MULTITOOL/STAFFMULTITOOL` |

For one request the bridge (`obtain_request.h`, with `ship_obtain.h` and
`multitool_obtain.h`) finds the carrier, checks that it holds seed 1, class S
and the expected type, writes the requested seed and class, calls the reward
routine and restores both. Only numbers are written; the scene text is never
touched, which is why there is one carrier per scene.

- Request `native-ship-request-180836-<PID>.txt` or `native-weapon-request-…`:
  `model=`, `seed=0x…`, `class=`; events `ship` and `weapon`. Result
  `result=offered`, `unknown_reward`, `bad_layout` or `not_ready`.
- Application: "Get a new one" under Starships and Multi-tools: kind, seed
  (empty draws a random one) and class.

## Starship kinds, checked on 2026-10-08

The game has nine starship types: shuttle, fighter, hauler, explorer, exotic,
interceptor, solar, corvette and living ship (the wiki's "Starship Archetypes"
section, read on 2026-10-08). The corvette is built from parts and has its own
area; the other eight are offered here.

Class and procedural scene of each kind are the game's own pairs, from the
ship models of `metadata/simulation/space/aispaceshipmanager` (build 180836):
`FIGHTER`, `DROPSHIP`, `SHUTTLE`, `SCIENTIFIC`, `SAILSHIP`, `ROYAL`
(`Royal`, `S-CLASS_PROC`), `ALIEN` (`Alien`, `BIOSHIP_PROC`) and `ROBOT`
(`Robot`, `SENTINELSHIP_PROC`).

No shipped reward uses the procedural scene of the last three; the game ships
them only with special models (`WRACER` and `WRACERSE` for `Royal`,
`BIOFIGHTER` for `Alien`, `VINTAGEINTERCEPTOR` for `Robot`). Their carriers
copy that reward (slots, size type, flags) and keep only these technologies,
dropping the special model's upgrades, trails and expedition extras:

| Kind | Technologies kept | Layout slots, size type (from the copied reward) |
| --- | --- | --- |
| Exotic | `HYPERDRIVE`, `LAUNCHER`, `SHIPJUMP1`, `SHIPSHIELD`, `SHIPGUN1`, `SHIPLAS1` | 36, `RoyLarge` |
| Living ship | `WARP_ALIEN`, `LAUNCHER_ALIEN`, `SHIPJUMP_ALIEN`, `SHIELD_ALIEN`, `SHIPGUN_ALIEN`, `SHIPLAS_ALIEN` | 20, `SciLarge` |
| Interceptor | `HYPERDRIVE_ROBO`, `LAUNCHER_ROBO`, `SHIPJUMP_ROBO`, `SHIPSHIELD_ROBO`, `LIFESUP_ROBO`, `SHIPGUN_ROBO` | 20, `RobotLarge` |

These are the entries the technology table marks `Core` for the kind, plus the
kind's basic weapons (`SHIPGUN1`, `SHIPLAS1`, `SHIPGUN_ROBO`, which are not
marked core). The generator fails if a listed technology is missing from the
copied reward.

The names shown for the eight kinds are the game's own in each language
(`BASESTATS_FIGHTER_L`, `_DROPSHIP_L`, `_SCIENTIFIC_L`, `_SHUTTLE_L`,
`_SAIL_L`, `_ROYAL_L`, `UI_S23_LIVING_SHIP_NAME`, `UI_S23_INTERCEPTOR_NAME`).
The game leaves the last two in English in several languages.

Multi-tools not offered yet: the game's multi-tool pool table
(`gcsimulationglobals`) pairs pool type `Exotic` with `ROYALMULTITOOL`,
`Sentinel` with `SENTINELMULTITOOL` and `Atlas` with `ATLASMULTITOOL`. No
shipped reward uses them and the stat class each needs is not confirmed.

## Not proven, and open

- For the exotic, living and interceptor kinds specifically: whether the game
  accepts the procedural scene in a specific-ship reward, and what the exotic
  looks like when the class asked is not S (in the game exotics are always S).

- Everything live. The in-memory layout of a reward entry was corrected after
  the first currency attempt and has not been confirmed by a successful
  request of any kind yet; a first `bad_layout` here would point at the same
  question.
- Whether the game honours the class written into the reward, and how many
  slots the offered item has. Full slots and supercharged slots are applied
  afterwards with "Upgrade".
- Not offered: royal, sentinel and atlas multi-tools (see above) and special
  models (expedition ships and multi-tools).
- Plain `.nmsship` ship files: they name a scene, a seed and a class. A file
  whose scene is one of the eight above could be delivered with this request;
  the file reader recognises such files but nothing maps them yet.
