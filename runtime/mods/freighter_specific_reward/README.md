# Freighter-specific reward experiment

This original sparse EXML patch defines `COURIER_FREIGHT` in the generic reward table. Its payload is based on the **installed build 179666** vanilla expedition-13 `RS_S13_S4M6` freighter reward, with the reward ID changed, inventory class set to S, and `ShipLayout.Slots` set to 120. The original reward already specifies a freighter scene, zero Units cost, and an inventory container. No third-party mod assets are included.

This file is **not installed**. A full-copy offline control compiled and decompiled with MBINCompiler 7.04.0.1 and retained `COURIER_FREIGHT`, type `Freighter`, class S, layout slots 120, and cost zero. This proves the serializer accepts the entry. It does **not** prove that `GiveGenericReward` can grant a freighter from ordinary gameplay, that the game opens an offer/exchange UI, that 120 general slots become unlocked, or that 60 technology slots are unlocked. The vanilla `ShipInventory.NumSlotsFromTech` value is zero, and its behavior is not established. The game may grant directly, show a claim screen, ignore the reward, or reject it.

The intended trigger is an on-demand Courier runtime command, eventually issued through the desktop frontend. The supplied Season Rewards and Meta-Mod archives were inspected as examples of `GcRewardAction` wiring, but this experiment does not add a Quick Action or other in-game button. It does not change global generation probabilities or other freighters.

For the first live test, the existing known-good currency DLL was kept unchanged because a separate freighter-offer DLL hung at startup. With NMS closed, the installed currency reward EXML was backed up and its `COURIER_QS` entry temporarily replaced by this `GcRewardSpecificShip` payload. This maps the known-good bridge's third one-shot event to the freighter reward for one process only; it does not grant Quicksilver while this test patch is installed. The combined EXML was compiled against the exact-build full reward table without warnings, and the installed EXML SHA-256 was verified as `0745a424670c848ee17e7df5621236bd11b355dd8bd8f0640f3a20abbc1f45a3`. The original EXML is preserved under `%TEMP%/NMSCourierFreighterLive20260923/REWARDTABLE.currency-original.EXML` (SHA-256 `d67a57493af349e6a50d624537e5fdce59fdfdd2d29a6e2a63366e6c817f08e7`).

NMS PID 24784 loaded the pinned executable and DLL, reached a ready 10 × 12 personal inventory with the previously observed 515 Carbon, and received one `COURIER_QS` bridge event. The hook log reported `currency_quicksilver_state=2`, meaning the native reward function call was dispatched. The user then supplied a screenshot of a freighter acquisition screen opened from ordinary gameplay without visiting a captain. It displayed a C-class freighter with 35 cargo and 21 technology slots, despite the reward EXML declaring S class and layout 120. The screen showed a market value of 98,500,000 Units but offered an `Obter nave cargueira` acquisition button. The user accepted it, reported owning the freighter, and reported that the Units balance remained 1,000,010,460. This proves a free local freighter offer and acquisition. It also proves that the game did not apply the specified S class or 120 layout slots to this generated offer. Sixty unlocked technology slots and persistence after a normal reload are not yet verified. The game autosaved on acceptance according to the user's observation. No second event was signaled. After NMS exited, the original currency EXML was restored and its installed SHA-256 matched the preserved `d67a57493af349e6a50d624537e5fdce59fdfdd2d29a6e2a63366e6c817f08e7` backup. The known-good DLL was unchanged throughout.
